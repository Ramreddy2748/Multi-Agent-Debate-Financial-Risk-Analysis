======================================================================
1. PROJECT STATUS
======================================================================

The project is an auditable, multi-agent stock-risk application. It
combines persisted financial data, specialist agents, retrieval-augmented
evidence, a critic/orchestrator, self-healing execution, FastAPI routes, and
an interactive frontend.

The system currently has four specialist agents and one critic/orchestrator:

1. Fundamental Agent
   Uses SEC/EDGAR-derived financial data and the fine-tuned FinBERT model.
   Main signals include cash, long-term debt, equity, net income,
   operating income, leverage, liquidity, and profit margins.

2. Market and Volatility Agent
   Uses Yahoo Finance price history and calculated market features. The
   primary experimental model is a Qwen LoRA adapter. A deterministic
   volatility rule path remains available when the remote model is missing,
   slow, malformed, or unavailable.

3. Sentiment Agent
   Uses NewsAPI headlines and ProsusAI/FinBERT sentiment inference. VADER
   remains available as a baseline fallback. The agent reports sentiment
   label, confidence, article count, and headline evidence.

4. Macro-Economic Agent
   Uses FRED macroeconomic series and the Macro v2 Phi-4-mini LoRA forecast.
   The rule-based FRED path remains available as a fallback.

5. Critic / Orchestrator Agent
   Combines the four specialist outputs, checks disagreement and evidence
   quality, produces the final risk verdict, and can use Claude when the
   Claude API key is configured. A local weighted critic remains available.

2. DATA PIPELINE UPDATES
======================================================================

The project follows a Bronze -> Silver -> Gold data flow.

Bronze:
- Raw Yahoo Finance price files
- Raw SEC/EDGAR filing data
- Raw FRED macroeconomic observations
- Raw NewsAPI headline data
- Raw files are retained as received for traceability

Silver:
- Cleaned and standardized price files
- Cleaned SEC financial records
- Cleaned macroeconomic data
- News sentiment aggregates and Parquet outputs
- Invalid or incomplete rows are handled explicitly rather than silently
  disappearing

Gold:
- Risk scores for the company universe
- Feature-priority outputs
- Freshness reports
- Training JSONL files
- Comparison reports and model outputs

3. RAG AND EVIDENCE UPDATES
======================================================================

The project now has two evidence retrieval layers.

A. Ticker-specific vector RAG
Files and index:
- agents/shared/retrieval.py
- data/gold/vector_store/

The vector index stores chunks created from Silver EDGAR, price, and news
data. Retrieval is filtered by ticker, so AAPL evidence cannot be returned
for MSFT or another company.

B. Curated financial-terms RAG
Files:
- data/rag/financial_terms.jsonl
- data/rag/agent_retrieval_config.json
- data/rag/README.md
- agents/shared/financial_rag.py

The curated RAG contains definitions, formulas, thresholds, priority rules,
and required evidence fields for terms such as:
- Debt-to-equity
- Cash-to-debt coverage
- Profit margin
- Operating margin
- Annualized volatility
- Beta
- Maximum drawdown
- Price versus 52-week high
- FinBERT sentiment
- Article count
- Agent disagreement
- Confidence floor
- Data provenance

Current enhancement completed:
- Fundamental LLM comparison prompts now receive both company evidence and
  curated fundamental definitions/thresholds.
- Market LLM comparison prompts now receive both company market/news evidence
  and curated volatility, beta, drawdown, and sentiment rules.
- Judge prompts also receive the curated rules when evaluating groundedness
  and consistency.
- The prompt records data/rag/financial_terms.jsonl as the curated source.

To rebuild vector RAG after refreshing Silver data:

    python3 agents/retrieval.py --build-all

5. SELF-HEALING AND RELIABILITY UPDATES
======================================================================

Added baseline and self-healing execution modes:

    SYSTEM_MODE=baseline
    SYSTEM_MODE=self_healing

Self-healing behavior:
- Detects malformed or incomplete specialist output.
- Detects internal JSON parse-error signals from the remote Market LoRA.
- Retries the affected agent once.
- Records attempt count and healing actions.
- Records data-quality warnings.
- Uses a conservative fallback if the retry still fails.
- Exposes execution mode in the verdict and frontend scorecards.

Market-specific reliability:
- Detects truncated or invalid JSON from the remote Qwen endpoint.
- Prevents an invalid response from being incorrectly labeled as a valid LoRA
  inference.
- Blends a remote model score with the feature-based score when the model
  strongly contradicts its own volatility and beta evidence.
- Caps confidence when calibration or fallback behavior is used.

Critic guardrails:
- Detects label disagreement.
- Detects large score spreads.
- Detects missing news coverage.
- Detects fallback claims and data-quality warnings.
- Detects stale, future, or mismatched as-of dates.
- Forces human review when evidence quality or freshness is unsafe.
- Caps final confidence when material review issues exist.
